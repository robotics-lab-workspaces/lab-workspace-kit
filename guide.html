はじめに

まず公式モデルの歩行を見たい場合は、GPUコンテナに入るところまで進み、同梱モデルの再生を実行してください。自分で学習する手順は後から試せます。

いま、どこに入力する？

Ubuntuデスクトップで Ctrl+Alt+T を押すとターミナルが開きます。入力待ちのときに表示される文字列を「プロンプト」と呼びます。各コマンドの上のラベルと、今のプロンプトを見比べてください。

Ubuntuのターミナル（ホスト）
labadmin@…$
Ubuntuホスト側です。ここで作業環境を開きます。
コンテナ内のターミナル
lab@mujina-gpu0-student01:/workspace$
student01のGPU 0環境に入ったときの例です。ここで学習・再生します。

「コピー」を押し、ターミナルをクリックして Ctrl+Shift+V で貼り付け、Enter で実行します。プロンプトや末尾の $ は入力不要です。次のコマンドはプロンプトが戻ってから入力します。sudo がパスワードを求めたら、文字が表示されなくてもそのまま入力し、Enter を押します。

フォルダーの場所を確認するには

~ は現在のユーザーのホームフォルダーです。コンテナ内の /workspace は作業ファイルの置き場所です。コンテナで pwd を実行すると今いる場所が表示され、ls でその中身を確認できます。cd /workspace で作業フォルダーに移動できます。

実行中の学習や再生を止めるには、そのターミナルで Ctrl+C を押します。プロンプトが戻った状態で exit を実行するとコンテナからUbuntu側へ戻ります。

新規セットアップと復旧

Ubuntu 24.04にDocker EngineとPython 3.12以上を用意すると、対話CLIで共有環境を準備できます。GPU版の条件とライセンスはREADMEを先に確認します。

Ubuntuホスト · 取得と対話メニュー
git clone https://github.com/robotics-lab-workspaces/lab-workspace-kit.git &&
cd lab-workspace-kit &&
./labctl

共通ファイルやコンテナが壊れたときは、クローン先で次を実行します。~/agent-lab/students の作業フォルダーと設定を見つけて、同じ作業名に接続します。

Ubuntuホスト · 残っている作業データから復旧
./labctl repair

別の場所からの復旧や、バックアップからの復元はREADMEの復旧手順を使います。

Dockerで起動

Ubuntuデスクトップのターミナルで、自分の作業名を指定します。student01 は例です。最初にDockerへ入れば、Isaac SimやMuJoCoは普段どおりUbuntuにウィンドウを開きます。

Ubuntuのターミナル · GPU 0
~/agent-lab/student-lab student01 --gpu 0

表示が lab@mujina-gpu0-student01:/workspace$ に変わったら入室完了です。下の3つは目的に合わせて1つ選んでください。学習を試す場合は学習手順に進みます。

GPU 1を使うときは --gpu 1、2枚をコンテナに割り当てるときは --gpu all を指定します。

Isaac SimでMuJinaを表示

コンテナ内 · GUI
mujina-isaac preview

プレビューは1体のモデルと物理をゼロ入力で確認するモードです。学習済みの歩行はポリシー再生で見られます。

MuJina ROSをMuJoCoで表示

コンテナ内 · GUI
mujina-ros-sim

画面なしでIsaacの動作を確認

コンテナ内 · 3ステップで終了
mujina-isaac preview --headless --steps 3

学習プロジェクトは /workspace/mujina_isaac_lab にあり、Ubuntu側の ~/agent-lab/students/作業名/workspace/ と共有されます。

学習

まず8環境・1反復で、CUDA、モデル読み込み、保存を試せます。画面を出して試すときは、Ubuntuデスクトップから入り、最後の --headless を外します。

コンテナ内 · 短い動作確認
mujina-isaac train --task Isaac-Velocity-Rough-Mujina-v0 \
  --num_envs 8 --max_iterations 1 --logger tensorboard --headless

出力先は /workspace/mujina_isaac_lab/logs/rsl_rl/ です。1反復のテストでは、チェックポイントと学習ログが作られることを確認できます。歩行を確認するときは、対象タスクで十分に学習したチェックポイントを選びます。

学習済みポリシーを再生

UbuntuデスクトップからGPUコンテナに入り、次のコマンドを実行します。RT公式の学習済み歩行ポリシーを読み込み、Isaac SimでMuJina 1体に前進を指示します。

コンテナ内 · 同梱ポリシーをGUIで再生
bash /workspace/policies/play-mujina.sh

終了は起動したターミナルで Ctrl+C。スクリプトが見つからなければ、Ubuntuデスクトップから同じ作業名で student-lab に入り直してください。

自分の学習結果を再生する

同じ作業環境内のRough-MuJinaの学習結果を使います。下の例は保存先にあるチェックポイントを選んで、再生スクリプトに渡します。特定の回を選ぶ場合は、checkpoint にそのファイルの絶対パスを指定します。

コンテナ内 · 自分のモデルをGUIで再生
logs=/workspace/mujina_isaac_lab/logs/rsl_rl/mujina_rough
checkpoint=$(find "$logs" -type f -name 'model_*.pt' 2>/dev/null | sort -V | tail -n 1)
if [ -n "$checkpoint" ]; then
  bash /workspace/policies/play-mujina.sh "$checkpoint"
else
  printf '%s\n' 'この環境には学習結果がありません。'
fi

bash が play-mujina.sh を起動します。最後に渡す .pt はモデルデータです。1反復の結果は、保存と読み込みの動作確認に使います。

再生時にファイルのエラーが出たら

cannot execute binary file が出たら、bash の直後が play-mujina.sh のパスか確認します。.pt を直接実行しようとした場合は、上のコマンドをまとめて貼り直します。

No such file or directory が出たら、指定した場所にファイルが見つかっていません。まず作業名を確認し、/workspace に目的のファイルが保存されているか確認します。自分の学習回は ls /workspace/mujina_isaac_lab/logs/rsl_rl/mujina_rough/ で確認できます。

TensorBoardで学習グラフを見る

学習中のターミナルはそのままにし、Ubuntuで Ctrl+Alt+T を押して2つ目を開きます。そこでも同じ作業名・GPU番号の起動コマンドを実行します。入室時に表示されるUbuntu側のURLを控え、コンテナのプロンプトに変わったら下のコマンドを実行します。TensorBoardは1コンテナにつき1つ起動し、グラフを見ている間はこの端末を開いたままにします。

コンテナ内 · 既定の学習ログを読む
mujina-tensorboard
コンテナ内
各コンテナで 6006
Ubuntu側
http://localhost:32771 など

TensorFlowがインストールされていないという通知が出ても、TensorBoardが起動したら続けて構いません。入室時に控えたURLをUbuntuのブラウザーで開きます。Ubuntu側の番号はDockerが空きを選ぶため、コンテナごとに異なります。停止・再開で変わることもあります。

Macから開く

下の 32771 をUbuntuで表示された番号に置き換え、Macで実行します。そのままMacのブラウザーで http://localhost:16006 を開きます。lab-host.example.org と labadmin は、接続先の管理者が指定する値に置き換えます。

Macのターミナル · SSH転送
ssh -N -L 16006:localhost:32771 labadmin@lab-host.example.org

Isaac Simの画面はUbuntuデスクトップ上のウィンドウです。この転送はTensorBoardのブラウザー画面に使います。 Dockerのポート公開仕様

各コマンドの上に、実行する場所を表示しています。labadmin@… はUbuntuホスト、lab@mujina-… はコンテナ内です。student01 を自分の作業名に置き換えてください。

画面やターミナルだけ閉じる

シミュレーターやTensorBoardは、起動したターミナルで Ctrl+C を押すと終了できます。次にコンテナのシェルを閉じると、Ubuntu側のプロンプトに戻ります。コンテナは起動したままです。

コンテナ内 · Ubuntuのプロンプトに戻る
exit

コンテナを停止する・再起動する

Ubuntuホスト側で、自分のコンテナ名を指定します。停止や再起動をすると、内部の学習・シミュレーター・TensorBoardも終了します。必要なチェックポイントを保存してから実行します。

Ubuntuホスト · 自分のGPU 0版を停止
sudo docker stop mujina-gpu0-student01
Ubuntuホスト · 自分のGPU 0版を再起動して入り直す
sudo docker restart mujina-gpu0-student01 &&
~/agent-lab/student-lab student01 --gpu 0

停止・再起動では、コンテナ内に追加したパッケージ、自分の作業ファイル、設定が残ります。TensorBoardは必要に応じて起動し直し、そのとき表示されたURLを使います。

標準環境に戻す

まっさらな標準環境で試すなら、未使用の作業名を指定します。元の環境には、元の作業名で戻れます。

Ubuntuホスト · 別の新しい作業名を作る
~/agent-lab/student-lab student01-clean --gpu 0
同じ作業名で、コンテナ本体だけ作り直す

自分のコンテナ名を確認してから実行してください。コンテナに直接入れた apt パッケージや、永続フォルダの外に保存したファイルは消えます。

Ubuntuホスト · 自分のGPU 0版だけを作り直す
sudo docker stop mujina-gpu0-student01 &&
sudo docker rm mujina-gpu0-student01 &&
~/agent-lab/student-lab student01 --gpu 0

/workspace のコード・学習ログと、同じモードの /home/lab の設定・認証はUbuntu側に保存されるので、同じ作業名で引き継がれます。コードも初期状態で試す場合は、別の作業名を使ってください。

稼働状況・GPU・CPUを確認

ここにあるコマンドはすべて、Ubuntuホストの labadmin@… で実行します。

開いているコンテナと、現在のCPU・メモリ使用量

Ubuntuホスト · 起動中の一覧と使用量
sudo docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
sudo docker stats --no-stream --format 'table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}'

停止済みの環境も含める場合は sudo docker ps -a。stats のCPU欄は現在の使用率で、複数の論理CPUを使うと100%を超えます。

GPUの割り当てを確認

Ubuntuホスト · ホスト全体と、自分のコンテナから見えるGPU
nvidia-smi --query-gpu=index,uuid,name,memory.total --format=csv
sudo docker exec mujina-gpu0-student01 \
  nvidia-smi --query-gpu=index,uuid,name,memory.total --format=csv

2行目の一覧が、そのコンテナから使えるGPUです。ホストでGPU 1を渡してもコンテナ内ではGPU 0と表示される場合があるので、両方の UUID を照合します。通常版はGPU割り当てなしです。

CPUとRAMの割り当て上限を確認

Ubuntuホスト · 全体容量と、自分のコンテナの実際の上限
nproc
free -h
sudo docker exec mujina-gpu0-student01 sh -c '
  printf "CPU quota: "; cat /sys/fs/cgroup/cpu.max
  printf "CPU IDs: "; cat /sys/fs/cgroup/cpuset.cpus.effective
  printf "Memory bytes: "; cat /sys/fs/cgroup/memory.max
'

CPU quota が max の場合、CPU時間の上限は設定されていません。CPU IDs は使える論理CPU番号、Memory bytes はRAMの上限です。既定の上限は通常版24 GiB、GPU版64 GiBです。

学生が触ってはいけない場所

普段の編集は自分の /workspace の中で行います。停止・再起動・作り直しの対象は、自分のコンテナ名を一覧で確認してから指定してください。

対象守ること
ほかの人の環境~/agent-lab/students/他の作業名/ のコード・学習ログ・認証と、他の人のコンテナは触らない。停止や削除も本人に任せます。
共通の起動設定~/agent-lab/student-lab、~/agent-lab/compose*.yaml、~/agent-lab/mujina-image/ は共用環境全体に関わります。実験コードは、自分の作業フォルダにあるコピーを編集します。
UbuntuとDockerの管理領域/etc/docker/、/etc/cdi/、/var/lib/docker/、GPUドライバー、ネットワーク設定は管理担当者が扱います。Docker全体を消す・止めるコマンドや docker system prune は使いません。
実機・認証情報シミュレーション作業中は、実機CAN・制御ノード・実機接続を触りません。SSH鍵、パスワード、APIキー、X11認証は作業ログやGitに貼りません。

共通設定に問題を見つけたときは、実行したコマンド、エラー、自分のコンテナ名を共有ルールに沿って管理担当者に伝えます。

トラブルの切り分け

Isaacのウィンドウが出ない

Ubuntuデスクトップのターミナルから student-lab に入り直して、mujina-isaac preview を実行します。初回は描画キャッシュの準備に時間がかかります。

ウィンドウは出たがロボットが歩かない

プレビューはゼロ入力です。対応する学習済み .pt を使う再生手順を確認します。

TensorBoardが開かない、グラフが空

「6006 already in use」（ポート6006は使用中）と表示され、同じコンテナでTensorBoardを起動済みなら、入室時に表示されたUbuntu側のURLをブラウザーで開くと、そのTensorBoardを利用できます。

同じ作業環境で mujina-tensorboard が動いていることを確認します。URLは今回表示されたものを使います。画面が開いてグラフが空なら、/workspace/mujina_isaac_lab/logs に学習のイベントファイルがあるか確認します。

CUDAエラーや Resource temporarily unavailable が出る

まずコンテナ内でGPUが見えているか確認します。pids.events の max が繰り返し増える場合、プロセス・スレッド上限に達しています。GPU版の上限は2048です。Isaacの詳細ログは ~/.local/share/mujina-isaac/logs/ にあります。

コンテナ内 · GPUとプロセス上限
nvidia-smi -L
cat /sys/fs/cgroup/pids.max /sys/fs/cgroup/pids.events

作業メモは自分の /workspace/WORKLOG.md へ。共有ルールは /workspace/AGENTS.md、環境の再ビルド手順は ~/agent-lab/mujina-image/README.md にあります。
